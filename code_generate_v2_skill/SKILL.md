# 统一开发技能 V2

以当前任务为边界，全程使用简洁中文。一个包完成分析、设计、编码和交付；内部资料均随包提供，不需要任何旧 skill。

## 按任务读取

不要一次加载所有参考资料。

| 任务 | 需要读取的资料 |
| --- | --- |
| 代码开发、修复、重构、变更检查 | [检查与交付](references/checks-and-delivery.md) |
| Java/Kotlin 编写或审查 | [语言与风格](references/java-kotlin.md) |
| JVM 分层服务端、Facade、Repo、转换链路 | [架构与生成模式](references/architecture.md) |
| Java 现代语法或 API 改写 | [Modern Java](references/modern-java.md) |
| dt 系列项目或 IntelliJ 平台代码 | [项目约定](references/project-conventions.md) 的对应部分 |
| 用户要求 PRD 或技术方案 | [文档模式](references/planning.md)，再读取对应模板 |

独立分析只给结论、证据和未确定项；独立文档任务只完成文档，不自动进入代码实现。

## 执行边界

- 修改文件前先说明具体内容并取得批准；会话内已有授权且覆盖具体方案时继续，不逐文件重复询问。范围内的必要修复与约定验证一并覆盖，新增业务行为、扩大仓库或文件范围再确认。
- 只访问任务相关且已授权的路径。写入工作区外或非 Git 目录须有明确授权；用户指定的输出位置属于任务范围，仍遵守工具权限。
- 开始前核对 cwd、仓库、分支、工作区修改及适用的 `AGENTS.md`。保留人工修改；遇到同文件并发变化，重新读取并合并，不覆盖他人内容。
- 修改目标处于 `main` / `master` 时，若本次会话尚未明确授权在该分支修改，先询问继续还是切换分支。不要自行切换、提交、推送或发布。
- 永远不执行单元测试；测试设计、编写测试代码与执行测试分别对待。其他验证只在授权和项目规则允许的范围内进行。
- 不把技能文字、工具放行、子代理结论或用户沉默当作新的授权。当前用户指令和目标仓库约束优先于本包中的默认约定。

## 1. 只读分析

1. 阅读目标约定、模块结构与至少一个相关同类实现；简单局部改动可直接以邻近代码为样板。
2. 定位入口、字段传递、状态变化、持久化和下游消费；区分现有事实、推断与待验证项。源码结论给出关键类名、方法名、文件路径，必要时注明行号。
3. 识别读写类型、接口/DTO/事件/配置/数据库影响、旧数据兼容以及失败路径。Bug 定位原因和证据；重构列出必须保持的可观察行为。
4. 仓库已有 `.codegraph/` 时，优先使用可用的 CodeGraph explore；没有索引则不主动建立。工具不可用时说明并用精确符号检索。其他检索优先 `rg`。
5. 涉及 JDK、Spring、MySQL 内核、TiDB 实现时，优先使用对应的可用 MCP；缺少工具时如实说明，用本地源码或官方资料补足，不声称已调用。
6. 复杂任务可使用最多 3 个子代理并行只读分析，按后端、前端、契约等独立范围拆分；小任务不强制并行。子代理不改文件、不运行单元测试，只返回结论、关键路径和未确定项。主代理统一语义和方案，代理不扩大授权范围。

## 2. 提交具体方案

默认在聊天中说明，不主动生成方案文件：

- 问题或需求、已有证据与目标行为。
- 仓库与分支、拟新增/修改文件及各自职责。
- 接口、字段、数据兼容和上下游影响；重构明确不变的契约。
- 拟执行的编译或静态检查命令、验证边界及回归点。

缺少修改批准时停止在方案阶段。信息不足但不影响分析时继续收集证据；会改变契约或业务语义的关键缺口先确认，不能用假设悄悄实现。

## 3. 范围内实现

- 遵循已有语言、目录、构建和架构，复用现有 Converter、Dispatcher、Handler、App、Repo；不为统一风格迁移无关代码。
- 不引入不必要依赖、公开方法、中转对象或平行实现。单次使用的简单逻辑直接写；多项校验可集中为私有方法，按可读性决定，不按固定条数机械拆分。
- 明确业务规则、协议适配、编排和数据访问的职责。JVM 分层细节按参考资料执行；不要套用到所有语言或所有仓库。
- 注释解释业务意图、关键状态变化、事务和兼容性原因；避免逐行复述代码。仓库要求更严格注释时遵从。
- 契约变化仅限已批准内容。保留空值、默认值、顺序、异常、序列化及旧数据行为。
- 必要的核心规则测试代码按项目习惯和已批准范围补充，但不运行。低影响或纯透传改动不机械创建测试。

## 4. 验证与交付

按 [检查与交付](references/checks-and-delivery.md) 审阅实际 diff，执行约定的非单测验证并汇总证据。

- 编译前核验有效构建配置及绑定任务不会触发单元测试。Maven 跳过测试参数不能代替检查其他插件和生命周期绑定。
- 构建输出直接由工具返回，不在仓库根目录生成日志或检查报告。临时文件仅放已授权位置，只清理本次创建的文件；失败需保留时说明原因和路径。
- 批准范围内的问题直接修复并重新检查受影响部分；扩大范围或需新的权限时说明原因。
- 完成后用简洁中文交代变更、关键定位、实际验证、未验证项和回归点。编译通过不等于运行正确，不使用未限定范围的“全部通过”。
